# Rules

Generated by `agentconf-audit rules --markdown`; `tests/test_docs.py` fails if this file drifts.

Severity is the default for a full match; a rule may emit a lower severity for a weaker match (each rule's text says when).

## CC001 · Bash allow-listed without restriction

- **Default severity:** HIGH
- **Applies to:** `claude-code-settings`
- **Why it matters:** `Bash`, `Bash(*)` or `Bash(*:*)` in permissions.allow lets the agent run any shell command without a prompt. Prompt injection in any file the agent reads becomes code execution.
- **Not caught:** Equivalent effects reached through defaultMode or a permissive hook are reported by CC003/CC004, not here.

## CC002 · Bash allow-list entry grants arbitrary code execution or destructive power

- **Default severity:** MEDIUM
- **Applies to:** `claude-code-settings`
- **Why it matters:** A prefix rule for an interpreter (`python3 *`), a downloader (`curl *`), a privilege tool (`sudo *`) or a leading wildcard (`*foo*`) is equivalent to unrestricted execution.
- **Not caught:** Only the first token is classified. `Bash(git *)` is not flagged even though git hooks and aliases can run code; wrapper scripts with innocent names are not inspected.

## CC003 · Permission prompts bypassed by default

- **Default severity:** HIGH
- **Applies to:** `claude-code-settings`, `claude-desktop-config`
- **Why it matters:** `permissions.defaultMode` of `bypassPermissions`/`dontAsk`, `skipDangerousModePermissionPrompt`, or the Desktop bypass opt-in removes the human from every tool call.
- **Not caught:** Bypass enabled per-invocation on the command line (`--dangerously-skip-permissions`) leaves no trace in config.

## CC004 · Lifecycle hook executes a shell command

- **Default severity:** INFO
- **Applies to:** `claude-code-settings`
- **Why it matters:** Hooks run on every matching tool call with the user's privileges. Their scripts are part of the trust boundary and should be reviewed like code.
- **Not caught:** The hook script's contents are not read. Only the command line is inspected for pipe-to-shell and unpinned package execution.

## CC005 · Credential stored in settings env

- **Default severity:** HIGH
- **Applies to:** `claude-code-settings`
- **Why it matters:** `env` values are injected into every tool process and are easy to leak via `settings.json` backups, dotfile repositories and screenshots.
- **Not caught:** Secrets passed through a helper (`apiKeyHelper`) or the OS keychain are the right pattern and are not inspected.

## CC006 · Project MCP servers auto-approved

- **Default severity:** MEDIUM
- **Applies to:** `claude-code-settings`
- **Why it matters:** `enableAllProjectMcpServers: true` starts every server declared in a repository's `.mcp.json` without asking. Cloning a malicious repository then runs its servers.
- **Not caught:** Servers approved individually under `enabledMcpjsonServers` are not evaluated for trust.

## CC007 · Additional directory grants whole-filesystem or home access

- **Default severity:** MEDIUM
- **Applies to:** `claude-code-settings`
- **Why it matters:** `permissions.additionalDirectories` widens the agent's file scope; `/` or the home directory defeats project isolation (SSH keys, browser profiles, other repositories).
- **Not caught:** Symlinks inside an allowed directory that point outside it are not followed.

## CC008 · Sandbox disabled

- **Default severity:** LOW
- **Applies to:** `claude-code-settings`
- **Why it matters:** With `sandbox.enabled: false`, shell commands run with the full privileges of the user instead of inside the OS sandbox, so a permission mistake has no second barrier.
- **Not caught:** Whether the sandbox is available on this platform/version is not checked; the key may be a no-op.

## CX001 · Codex never asks for approval

- **Default severity:** HIGH
- **Applies to:** `codex-config`
- **Why it matters:** `approval_policy = "never"` lets every command run without a human decision. Combined with `danger-full-access` (CX002) it is unattended arbitrary code execution.
- **Not caught:** Per-profile overrides under [profiles.*] are checked; a `--ask-for-approval` CLI flag at run time is not visible here.

## CX002 · Codex sandbox disabled (danger-full-access)

- **Default severity:** HIGH
- **Applies to:** `codex-config`
- **Why it matters:** `sandbox_mode = "danger-full-access"` removes the filesystem and network sandbox; the agent can read any file and reach any host as the user.
- **Not caught:** `workspace-write` with `network_access = true` is a weaker form reported as LOW; its writable roots are not enumerated.

## CX003 · Model provider reached over plaintext HTTP

- **Default severity:** HIGH
- **Applies to:** `codex-config`
- **Why it matters:** Prompts, code and credentials to `base_url`/`openai_base_url` travel unencrypted to a non-loopback host.
- **Not caught:** Loopback proxies are INFO only; what they forward to, and over what, is unknown.

## CX004 · Broad project trust

- **Default severity:** LOW
- **Applies to:** `codex-config`
- **Why it matters:** A `trusted` project skips the trust prompt and may auto-load that directory's instructions and MCP servers. Trusting `/` or the home directory trusts every repository; a very long trusted list suggests trust is granted reflexively.
- **Not caught:** Whether each trusted path still exists or what it contains is not checked.

## CX005 · Codex hook executes a shell command

- **Default severity:** INFO
- **Applies to:** `codex-config`
- **Why it matters:** Hooks run on lifecycle events with the user's privileges and belong to the trust boundary. Codex records a trusted hash per hook; a hook without one has not been approved.
- **Not caught:** The hook script's contents are not read.

## GEN001 · File could not be parsed or classified

- **Default severity:** INFO
- **Applies to:** `*`
- **Why it matters:** An unparseable or unrecognised file is not audited. Silence here would be a false 'clean' result, so it is reported explicitly.
- **Not caught:** Nothing inside the file is evaluated.

## GEN002 · Configuration file readable by other users

- **Default severity:** MEDIUM
- **Applies to:** `*`
- **Why it matters:** Agent configs commonly hold tokens and trust decisions. Group/world-readable mode lets any local account or process read them.
- **Not caught:** ACLs, container boundaries and Windows permissions are not evaluated; on Windows this rule is skipped.

## MCP001 · MCP server runs an unpinned package from a registry

- **Default severity:** MEDIUM
- **Applies to:** `claude-desktop-config`, `claude-code-state`, `claude-code-settings`, `mcp-servers-json`, `codex-config`
- **Why it matters:** `npx -y pkg`, `pkg@latest` or `uvx pkg` resolves and executes whatever the registry serves at launch time. A compromised or typosquatted release runs with your privileges on next start.
- **Not caught:** A pinned version is still only as safe as that release; integrity (lockfile/hash) is not verified.

## MCP002 · Credential embedded in MCP server configuration

- **Default severity:** HIGH
- **Applies to:** `claude-desktop-config`, `claude-code-state`, `claude-code-settings`, `mcp-servers-json`, `codex-config`
- **Why it matters:** Secrets in `env`, `args`, `headers` or the URL of a server are stored in plaintext and shared with every process that can read the file.
- **Not caught:** Secrets in files the server reads itself (`.env`, keychains) are out of scope.

## MCP003 · Remote MCP server reached over plaintext HTTP

- **Default severity:** HIGH
- **Applies to:** `claude-desktop-config`, `claude-code-state`, `claude-code-settings`, `mcp-servers-json`, `codex-config`
- **Why it matters:** Tool calls and results (often including file contents) cross the network unencrypted and can be read or modified in transit; a modified tool result is a prompt-injection vector.
- **Not caught:** Loopback `http://127.0.0.1` is reported as INFO only; what the local proxy forwards to is unknown.

## MCP004 · MCP server command downloads and executes remote code

- **Default severity:** HIGH
- **Applies to:** `claude-desktop-config`, `claude-code-state`, `claude-code-settings`, `mcp-servers-json`, `codex-config`
- **Why it matters:** `curl … | sh` style launchers fetch arbitrary code on every start with no pinning or integrity check.
- **Not caught:** Installers invoked indirectly by a script file are not detected.

## MCP005 · MCP server command resolved through PATH or launched from a temporary directory

- **Default severity:** LOW
- **Applies to:** `claude-desktop-config`, `claude-code-state`, `claude-code-settings`, `mcp-servers-json`, `codex-config`
- **Why it matters:** A bare command name is resolved by PATH at launch; a writable earlier PATH entry or a temp directory lets another process substitute the binary.
- **Not caught:** PATH contents and directory permissions are not inspected; common runtimes (`node`, `python3`, `npx`, …) are deliberately exempt, so a hijacked `node` is not reported. A hygiene signal, not proof of exposure.

## MCP006 · MCP server granted whole-filesystem or home-directory scope

- **Default severity:** MEDIUM
- **Applies to:** `claude-desktop-config`, `claude-code-state`, `claude-code-settings`, `mcp-servers-json`, `codex-config`
- **Why it matters:** Filesystem-style servers take allowed roots as arguments; `/`, `~` or the home directory exposes every credential and repository on the machine to the model.
- **Not caught:** Scope passed through environment variables or a server-specific config file is not read.
